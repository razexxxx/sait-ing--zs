# Сайт о Республике Марий Эл

## Запуск

Нужен Node.js 24 или новее. Установка зависимостей: `npm ci`.
В Windows PowerShell при блокировке `npm.ps1` используйте `npm.cmd`.

Локальный `.env` уже создан со случайным секретом. При новом развёртывании
скопируйте `.env.example` в `.env` и задайте уникальный `SESSION_SECRET`
длиной не менее 32 символов. Случайное значение можно получить командой:

```sh
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

`npm start` запускает сайт по адресу http://localhost:3000.
`npm run dev` включает перезапуск при изменении файлов.
Порт настраивается переменной `PORT`. `.env` не публикуется и исключён из Git.

## Этап 1

- Клиентские файлы и обе папки изображений перенесены в `public/`.
  Прежние URL `/app.js`, `/styles.css`, `/image/...`, `/uploads/...` сохранены.
- База, сервер, зависимости и cookie не входят в публичную папку.
- Лимиты на IP за 15 минут: 100 общих запросов (включая статику),
  5 суммарных запросов входа/регистрации, 10 суммарных попыток создания
  постов и комментариев. Ответ 429 содержит сообщение и Retry-After.
- JPEG/PNG: до 5 МиБ, проверка имени, MIME, реального формата,
  полного декодирования, лимит 25 млн пикселей. Изображения перекодируются
  без исходных метаданных. Повреждённые и многостраничные файлы отклоняются.
  Такой контроль не является антивирусным сканированием.
- Клиент передаёт дополнительное поле `image_name`. Старый API с одним
  `image_base64` сохранён: расширение выходного файла выбирается по
  проверенному формату. Исходное имя без передачи серверу проверить невозможно.
- Блокировка проверяется на защищённых запросах и `/api/me`, сессия
  блокируемого пользователя завершается. Админские маршруты используют ту же проверку.
- Новых таблиц и эндпоинтов на этом этапе нет. Существующие данные не мигрировались.
- Добавлены dotenv, express-rate-limit, sharp; overrides для исправленных
  body-parser и qs сохраняют Express 4. После установки npm сообщает 0 уязвимостей.

## Проверки

`npm test` запускает шесть групп HTTP-интеграционных тестов: изоляция файлов,
регистрация и доступ, изображения, блокировки, три вида лимитов, существующие
операции с постами и комментариями. Для тестов создаются отдельные проекты
в `.test-work/`; настоящая база и фотографии не используются для записи.
Каталог исключён из Git и содержит только тестовые данные.

Сервер проверен запуском `npm start`. Контрольные суммы существующей базы
и всех 16 изображений после переноса совпадают с исходными.
Визуальная проверка, мобильный режим, консоль браузера и время полной загрузки
не проверены: в текущей среде нет подключённого браузера.

## Ограничения перед публичным размещением

Этап 1 не означает готовность всей системы к публичному запуску.
Демонстрационные аккаунты и подсказки из исходного проекта сохранены,
поскольку существующие записи изменять запрещено. Перед публикацией нужно
отдельно заменить демонстрационные пароли и убрать подсказки.
Сессии и счётчики лимитов пока находятся в памяти одного процесса и
сбрасываются при перезапуске. Для нескольких серверов потребуется общее хранилище.
В режиме `NODE_ENV=production` cookie требует HTTPS; для reverse proxy
нужно отдельно настроить доверие только к используемому прокси.

Этапы 2–5 не начаты: по заданию переход требует подтверждения пользователя.

Использованная документация:
[sharp](https://sharp.pixelplumbing.com/api-constructor/),
[express-rate-limit](https://express-rate-limit.mintlify.app/reference/configuration).
